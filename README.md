# 旅規ナビ 0.17

公開URL: https://ryoki-navi-trial.motofukuoka-ryoki.workers.dev/

JR北海道の旅客営業規則と、道内の交通系ICカードの公式資料をもとに、出典付きで回答するWebアプリです。利用者の登録・ログインと、端末へのAIモデル保存は不要です。

## 画面と操作

質問、回答、出典を中心とした1ページの構成です。接続案内の常設バナー、再接続ボタン、履歴一覧、共通利用のチェックは表示しません。質問欄と回答欄は通常のページの流れに置き、画面内の別スクロール領域や固定入力欄を作りません。回答・途中表示の到着時にスクロール位置を操作しません。Enterは改行で、送信ボタンから質問します。

再読み込み時に過去の質問一覧や以前の回答を画面へ復元しません。回答は内部管理と共通回答の再利用のため保存します。「続けて質問」または直前の回答を指す質問では、現在のページで直前に表示した回答を会話の前提に使います。その会話を共通回答にはしません。「新しい質問」で前提を解除できます。

原文、適用条件、共通回答の照合条件は必要に応じて開けます。資料一覧、回答のコピー・ファイル保存も利用できます。表示文言は「サーバ」に統一しています。

## 初めての質問への処理

共通回答に一致しない質問でも、公式資料から確認済みの規則で確定できる条件は直接判定します。質問文の完全一致だけを条件にしません。

- Kitacaの札幌・旭川エリアと函館エリア、駅の組合せ、エリアをまたぐ乗車、Suica等との相互利用、SAPICAとの違い。
- Kitacaの残額に応じた払戻し計算（非定期・1枚・10円単位の明示残額など、確認した条件の範囲）、デポジット、チャージ上限、入場券・途中下車の取扱い。
- 普通列車の自由席で、付き添いの大人の人数と、同一年齢の1〜5歳児の人数が明示された場合の幼児人数計算。
- 既存の確認済み基本案内と条文原文の表示。

追加条件や対象外条件がある場合、カード・人数・金額の対象が曖昧な場合、過去・将来の適用を確認できない場合は、通常のAI読解に進みます。計算の前提と出典を表示します。資料の版が変わると、確認済み案内は自動で無効になります。

通常のAI回答は、BGE-M3と語句検索、Gemma 4による資料選択、Qwen 3.8 27Bによる読解・条件照合を使用します。読解モデル、low推論、温度0、4,096トークンの生成予算を維持しています。根拠や必要な例外を省いて速度を出す方式には変更していません。

公開資料を一定の順序で先頭へ置き、利用者や質問と独立した公開資料の識別子を`x-session-affinity`に設定して、同じ資料を使う別の初回質問でもプロバイダのprefix cachingを利用しやすくしています。キャッシュの保持・ヒットはプロバイダが制御するため、常に高速化する保証はありません。

読解結果はストリームで受け取り、結論とその原文参照IDが完成し、収録原文との対応を確認できた時点で、結論から途中表示します。参照IDを検証できない結論、不完全な説明、推論トークンは利用者へ送信しません。最終回答全体も検証し、完了前の表示は履歴・共通回答へ保存しません。途中表示後に検証や通信が失敗した場合は、最終的な原文表示・エラーへ更新します。

無料サービスの混雑とモデル自身の推論時間は残ります。初めての個別AI質問がすべて数秒で完了する保証や、全質問の所要時間が同じになる保証はありません。回答内容の完全な正確性も保証しません。

## 収録資料と適用範囲

2026年11月21日確認時点で46文書・816区分、意味検索用の公式本文・案内459区分です。既存の旅客営業規則・改正公告等35文書の本文は変更せず、11文書・56区分を追加しました。

追加資料には、JR北海道のICカード乗車券取扱規則（第1〜39条・別表を含む19ページ）、Kitacaの利用可能エリア・利用案内・公式FAQ、2028年春予定のエリア拡大発表、JR東日本の北海道Suica利用案内、SAPICAの公式案内、函館バスの相互利用・ICAS nimoca案内を含みます。2028年の予定は現行エリアに混ぜません。

旅客営業規則の「第22条」と、ICカード乗車券取扱規則の「第22条」は別の識別子で管理します。IC専用規則を優先し、一般規則の参照や他事業者の案内は適用範囲を区別します。公開規則には省略・未統合の改正があり、JR東日本の旅客営業規則全文や企画乗車券の専用規則は未収録です。

## 保存・共通回答

完了した質問・回答はCloudflare D1に保存します。ブラウザの識別はランダムなHttpOnly・Secure・SameSite=Strict・ホスト限定Cookieを使い、DBには識別値のハッシュを保存します。他の利用者が個人の質問一覧を取得することはできません。画面は一覧を取得しません。既存の履歴データを削除・公開・一括移行しません。

新しい画面は`shareAnswer:true`と`semanticReuse:true`を送信し、単独の規則質問を共通で再利用します。共通領域には質問文・回答・検索ベクトル・抽出条件を保持しますが、Cookie、利用者の識別値、チャットID、私的な会話履歴・比較メモは含めません。画面下部と「利用について」で保存を説明します。個人情報は入力しないでください。個人情報を検出した質問、会話の続き、APIで共有を指定しない質問は共通領域の対象外です。自動検出があらゆる個人情報を見つける保証はありません。

完全一致は索引で返します。言い換えは、人数と対象・年齢・券種とカード名・使用状態・日時・経路・重量等の明示条件を照合したうえで、BGE-M3とGemma 4が意味と適用条件を比較します。同分野80件と同じ範囲の80件から最大2候補を比較し、類似度だけでは再利用を認めません。照合には合計8秒の上限を設け、相違・不確実性・時間切れは通常の読解へ戻します。

確認済みの言い換えは元の回答を指す別名として保存します。次の同じ言い換えでは再分析を省略します。別名を新しい意味照合の基準にはしません。再利用時にも、資料・処理の版と引用原文を照合します。個人履歴からの完全一致の再利用は同一識別・同一条件・7日以内に限定します。資料・処理の版が変わると古い回答は再利用せず、過去の保存データ自体は残します。

## 費用・開発

Cloudflare Workers Free、Workers AIとD1の無料枠で運用します。有料プランや有料AIへの自動切替はありません。無料枠には利用量・保存量等の上限があり、到達時や障害時は回答や保存ができない場合があります。

公式条件: https://developers.cloudflare.com/workers-ai/platform/pricing/ 、 https://developers.cloudflare.com/d1/platform/pricing/

Node.js 22.13以降で`npm ci`、`npm run typecheck`、`npm run build`を実行します。ビルドはAIを呼びません。`FREE_PLAN_CONFIRMED`の既定値は`0`です。運用者がWorkers Freeを確認したうえで`wrangler deploy --var FREE_PLAN_CONFIRMED:1`を使います。

D1の`DB`バインディングを設定し、`migrations/0001`〜`0005`を適用します。0.17で新しいDBや本番スキーマ変更は不要です。ローカル確認は`wrangler d1 migrations apply ryoki-navi-history --local --config wrangler.preview.jsonc`、`wrangler dev --config wrangler.preview.jsonc`を使います。

資料更新時は公式本文・案内を確認し、`scripts/build-semantic-index.mjs`で対応する索引を再生成します。認証情報・Cookie・履歴DB・共通回答DB・`.wrangler`・依存ライブラリやビルド成果物を公開ソースZIPへ含めないでください。
